ROAD TO HALL OF FAME

Ruta de progreso de laboratorios prácticos de File Path Traversal. Cada nodo representa una evidencia técnica documentada con su respectivo análisis de vulnerabilidad, payload y mitigación.

File Path Traversal — Simple Case

Apprentice Path Traversal Burp Suite
Objetivo: Acceder a archivos sensibles del servidor manipulando el parámetro filename mediante secuencias ../.

Descripción técnica: La aplicación carga imágenes de productos usando una ruta relativa sin validar la entrada del usuario. Al interceptar la petición GET en Burp Suite y reemplazar el valor por ../../../etc/passwd, el servidor normaliza la ruta y devuelve el contenido del archivo objetivo.
[ Sube tu captura: request + payload + respuesta vulnerable + Lab Solved ]
Payload: filename=../../../etc/passwd

Traversal Blocked — Absolute Path Bypass

Apprentice Absolute Path Bypass
Objetivo: Leer archivos del sistema cuando la aplicación bloquea secuencias de traversal relativas.

Descripción técnica: El servidor sanitiza entradas con ../ pero acepta rutas absolutas. Al enviar filename=/etc/passwd directamente desde la raíz del sistema, se omite el directorio base de imágenes y se accede al archivo solicitado.
[ Sube tu captura: Repeater con /etc/passwd absoluto + respuesta 200 OK ]
Payload: filename=/etc/passwd

Traversal Stripped — Non-Recursively

Apprentice Filter Bypass URL Encoding
Objetivo: Bypassar un filtro que elimina secuencias ../ de forma no recursiva.

Descripción técnica: El servidor aplica un filtro que borra ../ una sola vez. Anidando la secuencia como ....//, tras el primer filtrado queda ../, permitiendo el traversal. También aplica codificación URL doble.
[ Sube tu captura: Payload anidado o doble URL-encode + Lab Solved ]
Payload: filename=....//....//....//etc/passwd

Traversal Stripped — Superfluous URL-Decode

Apprentice Double Decode Burp Suite
Objetivo: Explotar una doble decodificación URL para restaurar secuencias de traversal bloqueadas.

Descripción técnica: La aplicación decodifica la entrada, aplica el filtro, y decodifica nuevamente. Enviando %252e%252e%252f (doble codificación de ../) permite que el payload sobreviva al filtrado y se interprete correctamente.
[ Sube tu captura: Request con %252e%252e%252f + respuesta con /etc/passwd ]
Payload: filename=%252e%252e%252fetc/passwd

Validation of Start of Path

Apprentice Path Validation Traversal
Objetivo: Bypassar la validación que exige que la ruta comience con un directorio esperado.

Descripción técnica: El parámetro contiene la ruta completa /var/www/images/. El servidor valida el prefijo pero no la continuación. Al enviar /var/www/images/../../../../etc/passwd, el prefijo es válido y la normalización apunta a /etc/passwd.
[ Sube tu captura: Repeater con prefijo válido + traversal + Lab Solved ]
Payload: filename=/var/www/images/../../../../etc/passwd

Validation of File Extension — Null Byte Bypass

Apprentice Null Byte Extension Bypass
Objetivo: Bypassar la validación de extensión de archivo usando el byte nulo %00.

Descripción técnica: La aplicación verifica que el nombre termine en .png. Al inyectar ../../../etc/passwd%00.png, el byte nulo trunca la cadena en el sistema subyacente, abriendo /etc/passwd mientras la validación ve .png.
[ Sube tu captura: Request con %00.png + respuesta con contenido de /etc/passwd ]
Payload: filename=../../../etc/passwd%00.png
