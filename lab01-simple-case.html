Lab 07: File Path Traversal — Simple Case

PortSwigger Web Security Academy | Herramienta: Burp Suite Community Edition

01_Nombre del laboratorio

File Path Traversal, Simple Case

URL del laboratorio: https://portswigger.net/web-security/file-path-traversal/lab-simple

El laboratorio consiste en una tienda en línea ("WE LIKE TO SHOP") cuya carga de imágenes de productos es vulnerable a recorrido de rutas. Para resolverlo, se debe recuperar el contenido del archivo /etc/passwd del servidor.

Evidencia 1: Página de descripción del laboratorio en PortSwigger Web Security Academy (estado inicial: "Not solved").
Evidencia 2: Acceso a la instancia del laboratorio — tienda "WE LIKE TO SHOP".

02_Nivel

Apprentice (principiante).

Este laboratorio es la introducción a la vulnerabilidad de recorrido de rutas, donde la aplicación no aplica ninguna validación sobre la entrada del usuario.

03_Tipo de explotación

File Path Traversal (también conocido como Directory Traversal o recorrido de directorios), clasificado dentro de las vulnerabilidades de lectura arbitraria de archivos (Arbitrary File Read).

La vulnerabilidad ocurre cuando una aplicación web utiliza nombres de archivo proporcionados por el usuario para abrir o cargar archivos del servidor, sin validar ni sanitizar la entrada. El atacante manipula la ruta con secuencias de retroceso de directorio (../) para navegar fuera del directorio previsto y acceder a archivos sensibles del sistema de archivos.

Si no existe validación, el atacante puede enviar:

GET /image?filename=../../../../etc/passwd

El servidor recibe la cadena completa y, al no estar mitigado, la resuelve y muestra el contenido del archivo del sistema operativo.

¿Qué archivos puede intentar leer un atacante?

  • Linux: /etc/passwd, /etc/shadow, /var/log/apache2/access.log, archivos privados de usuarios en /home/
  • Windows: C:\Windows\system.ini, C:\Users\<Usuario>\...

Consecuencias: lectura de archivos sensibles, obtención de credenciales de base de datos, conocimiento de la estructura interna del servidor, lectura de logs y metadatos de sesión, e identificación de rutas para ataques mayores (RCE, LFI, explotación de carga de archivos).

04_Objetivo del laboratorio

Demostrar la explotación de una vulnerabilidad de File Path Traversal mediante la manipulación del parámetro filename de la petición HTTP que carga las imágenes de los productos, con el fin de leer el contenido del archivo /etc/passwd del servidor y obtener la confirmación de "Lab solved" en la Web Security Academy.

05_Explicación técnica de la vulnerabilidad

La tienda en línea del laboratorio carga las imágenes de los productos a través de una petición HTTP GET con un parámetro filename que indica el nombre del archivo de imagen:

GET /image?filename=71.jpg HTTP/2

El servidor concatena este valor a su directorio de trabajo (por ejemplo, /var/www/images/) y devuelve el archivo solicitado.

La falla de seguridad

El servidor confía ciegamente en la entrada del usuario: no verifica que el nombre del archivo corresponda a un archivo real de imágenes, no elimina las secuencias ../ y no restringe la lectura a su directorio de trabajo. Esto viola el principio de validación de entradas y el de mínimo privilegio en el acceso al sistema de archivos.

Principio de defensa que se vulnera

La ruta canónica (la ruta real y definitiva tras normalizar ../, ./ y enlaces simbólicos) nunca se comprueba contra el directorio permitido. En un sistema correctamente defendido, la aplicación debería verificar que la ruta resultante siga dentro del directorio base antes de abrir el archivo.

07_Explicación del payload

Payload utilizado:

../../../../etc/passwd
ElementoFunción
../ Secuencia de retroceso de directorio (parent directory). Cada ocurrencia le indica al sistema de archivos que suba un nivel en la jerarquía de directorios.
../../../../ Cuatro retrocesos consecutivos. Partiendo del directorio de trabajo del servidor (/var/www/images/), los retrocesos consumen los niveles images/, www/, var/ y la raíz /, hasta posicionarse en el directorio raíz del sistema de archivos.
etc/passwd Ruta del archivo objetivo relativa a la raíz. El archivo /etc/passwd es legible por cualquier usuario en Linux y contiene la lista de cuentas del sistema, lo que lo convierte en el objetivo clásico para demostrar lectura arbitraria de archivos sin necesidad de privilegios elevados.

¿Por qué funciona? El servidor construye la ruta concatenando su directorio base con la entrada del usuario sin sanitizar:

/var/www/images/ + ../../../../etc/passwd → /etc/passwd

El sistema operativo normaliza la ruta resolviendo los ../, y el resultado final apunta directamente a /etc/passwd. Como la aplicación abre cualquier ruta que recibe, el contenido del archivo se devuelve en el cuerpo de la respuesta HTTP. La ausencia total de validación (filtros de secuencias, listas blancas o verificación de ruta canónica) es lo que hace posible el ataque.

08_Mitigación recomendada

  1. No pasar la entrada del usuario directamente a las APIs del sistema de archivos. Es la medida más efectiva. En su lugar, usar identificadores indirectos (IDs numéricos) mapeados del lado del servidor a archivos permitidos.
  2. Validación con ruta canónica. Obtener la ruta real del archivo (getCanonicalPath() en Java, realpath() en PHP, os.path.realpath() en Python) después de que el sistema operativo elimine ../, ./ y enlaces simbólicos, y verificar que comience con el directorio base permitido.
  3. Lista blanca de archivos permitidos. Aceptar únicamente nombres de archivo que coincidan con un patrón conocido y seguro (por ejemplo, solo alfanuméricos con extensión .jpg).
  4. Listas blancas de valores aceptados para cualquier parámetro que influya en la resolución de rutas.
  5. Ejecución del proceso del servidor con el mínimo privilegio, para que un archivo comprometido exponga la menor cantidad de información posible.
  6. Uso de un sistema de almacenamiento separado (por ejemplo, servir las imágenes desde un servicio dedicado o un bucket con acceso restringido), de modo que la aplicación web no tenga acceso directo al sistema de archivos del servidor.

09_Conclusión

El laboratorio demuestra de manera práctica cómo una omisión aparentemente menor —no validar un parámetro— permite a un atacante remoto leer archivos arbitrarios del servidor sin autenticación. La vulnerabilidad de File Path Traversal evidencia la importancia de la validación de entradas, el principio de mínimo privilegio y la verificación de rutas canónicas como controles fundamentales en la seguridad de aplicaciones web.
