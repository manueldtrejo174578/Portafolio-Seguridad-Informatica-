SNAKEOIL | Writeup técnico

[ Walkthrough técnico completo ]

Este proyecto detalla la resolución de la máquina vulnerable SNAKEOIL de la serie digitalworld.local publicada en VulnHub. La resolución incluye el encadenamiento de una puerta trasera en una API REST, inyección de comandos, escalada de privilegios y análisis de código fuente.

1. Introducción y mapa de ataque

SNAKEOIL es una máquina vulnerable de la serie digitalworld.local publicada en VulnHub. La descripción del laboratorio sugiere que el proyecto es un servicio web con componentes "de dudosa calidad" (snake oil), lo que anticipa una aplicación con funcionalidades ocultas y mala higiene de secretos.

El reto no depende de una sola falla. La resolución consiste en encadenar: una puerta trasera (backdoor) expuesta en una API REST, una inyección de comandos del sistema operativo, una reverse shell para obtener un intérprete interactivo, la lectura del código fuente de la aplicación que expone secretos hardcodeados y, finalmente, la reutilización de uno de esos secretos como contraseña para escalar a root.

Mapa de la cadena de ataque:

2. Preparación del entorno de laboratorio

El laboratorio se montó de forma aislada para garantizar que las pruebas no afectaran redes externas ni terceros:

  • Máquina atacante: Kali Linux (192.168.138.128) con herramientas de pentesting.
  • Máquina objetivo: digitalworld.local: SNAKEOIL (VulnHub), importada en VMware Workstation.
  • Red: segmento aislado tipo host-only/VMnet entre ambas máquinas; sin salida a Internet.

Al arrancar el objetivo se observa el entorno gráfico con un usuario local visible: patrick.

Captura 1 — Pantalla de inicio de sesión del objetivo: usuario local "patrick" visible.

3. Reconocimiento inicial

3.1 Descubrimiento de hosts (arp-scan)

La primera tarea fue identificar la dirección IP del objetivo dentro del segmento aislado utilizando arp-scan.

arp-scan -I eth0 -l

El sondeo reveló el objetivo en 192.168.138.130 con prefijo MAC de VMware.

Captura 2 — arp-scan: el objetivo 192.168.138.130 identificado por su MAC VMware.

3.2 Escaneo completo de puertos y servicios (Nmap)

Se ejecutó un escaneo completo de puertos TCP con detección de servicios, versiones y sistema operativo.

nmap -sC -sV -O -p- -T4 192.168.138.130
Captura 3 — Ejecución del escaneo Nmap completo contra 192.168.138.130.
Captura 4 — Resultados de Nmap: puertos 22, 80 y 8080.

3.3 Verificación del sitio web (puerto 80)

La visita al puerto 80 muestra una página estática de confirmación: "Welcome to SNAKEOIL!".

Captura 5 — Página principal del puerto 80: mensaje estático "Welcome to SNAKEOIL!".

4. Enumeración web y descubrimiento de la API

4.1 Fuzzing de directorios (Gobuster)

Ante una superficie web mínima, se procedió a descubrir rutas ocultas mediante fuzzing sobre el puerto 8080.

gobuster dir -u http://192.168.138.130:8080 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
Captura 6 — Gobuster sobre el puerto 8080: descubrimiento de endpoints de API y rutas del blog.

5. Registro y autenticación en la API (JWT)

El endpoint /registration acepta JSON y crea usuarios sin ninguna validación adicional. Posteriormente, el endpoint /login devuelve tokens de acceso JWT.

Captura 7 — Registro y login en la API: obtención de access_token y refresh_token JWT.

6. Endpoint /secret y obtención de la clave

Recordando el 500 de /secret, se probó enviando la cookie de sesión obtenida, lo que filtró la clave del backdoor commandexecutionissecret.

Captura 8 — Petición a /secret con cookie JWT: filtrado de secret_key.

7. Explotación del backdoor /run

El backdoor /run incluye una lista negra de cadenas prohibidas y un timeout de 1 segundo.

10. Escalada de privilegios: sudo su → root

La contraseña no era un secreto nuevo, sino la JWT_SECRET_KEY reutilizada para el usuario.

Captura 20 — Escalada final: sudo su con la contraseña reutilizada → shell como root.

11. Intentos fallidos y pruebas SSTI

Se probó Server-Side Template Injection (SSTI), pero el contenido de los posts se almacena y renderiza literalmente, descartando el vector.

Captura 21 — Prueba de SSTI: envío de {{7*7}} al post /1/edit.
Captura 22 — Payload SSTI {{7*7}} utilizado en la prueba.
Captura 23 — Vista del post tras la edición: el payload se almacenó literal.

12. Mitigaciones

HallazgoMitigación
Backdoor /run con clave fijaEliminar puertas traseras; proteger paneles administrativos.
Inyección de comandos (shell=True)Nunca construir comandos con entrada del usuario; usar listas de argumentos sin shell.
JWT_SECRET_KEY hardcodeadaExternalizar secretos a variables de entorno o un gestor de secretos.
Reutilización de contraseñaUn secreto, un propósito; aplicar políticas de complejidad y contraseñas únicas.
